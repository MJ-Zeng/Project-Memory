# B5A.1 整改交接（PM-02 → PM-03 / 人类）

## 0. 本轮缘由

PM-01 复现了上一候选 `85b1a4e` 的阻断缺陷：`pyproject.toml` 的 `[project.scripts] project-memory = "_project_memory_launcher:main"` 属 pip `module:function` 形式。pip 生成的入口体是 `from _project_memory_launcher import main`，该顶层模块名在**未隔离**的解释器里经环境 `sys.path` 解析；`PYTHONPATH` 或位于 `sys.path` 上的 cwd 中的同名 `_project_memory_launcher.py` 会抢先执行，打印 `FAKE_LAUNCHER`、exit 0，启动器主防线从不运行。

本轮把受支持入口从 `module:function` 换成**原生 OS 包装器**，在解析任何 Python 模块名之前完成隔离。

## 1. 结果

- 代码提交 `9288818`（9 文件，+279/−53；新增 `bin/project-memory` mode 100755、`bin/project-memory.cmd` mode 100644），证据提交 `eb084ae`，基线 `ddd9dba`，分支 `fix/b5a-module-shadowing`。
- 受信入口改为两级原生包装器：`bin/project-memory`（POSIX sh）/ `bin/project-memory.cmd`（Windows）经 OS `PATH`/绝对路径调用，**不经过 Python `sys.path`**；其第一件事是用 `-I -P` 启动解释器，再按**绝对路径**运行包外启动脚本 `_project_memory_launcher.py`（不再作为可按名字导入的 console 目标）。
- `pyproject.toml` 移除 `[project.scripts]` 与 `py-modules`，改用 `[tool.setuptools] script-files` 把两个包装器与启动脚本装入 `Scripts/`（bin）。
- 启动脚本与 `project_memory/__main__.py` 的**逻辑未改**，仅更新 docstring 说明其现在由包装器按绝对路径、在 `-I -P` 下运行；`__main__.py` 守卫保留为纵深防御。
- 全量测试 **226 passed / 2 skipped**（上一候选 220/2，本轮 `tests/test_security_b5a.py` 由 7 增至 13 passed）；无删除、无新增 skip。

## 6. NOT VERIFIED / 残余风险

1. **裸 `python -m` 且假冒包在模块解析阶段胜出**（例如 `/tmp` 下 `PYTHONPATH` 指向假冒包）：解释器先执行假冒包，产品代码没有机会运行，任何包内检查都无效。ADR §7.2 记录为固有边界；受支持的受信入口是原生包装器 / 绝对路径启动器 / `-I -P`。本项在证据包 `bare/residual-*` 中保留为 marker 出现的基线行为，**不视为通过**，最终判定交给 PM-03。
2. **POSIX 安装布局未端到端验证**：console 入口只在 Windows venv（Python 3.12.4）实测；`bin/project-memory`（sh）逻辑同源但未在 POSIX 安装后端到端跑通。
3. **`script-files` 已弃用**：`pyproject.toml` 用 setuptools 80.9.0 仍支持但已弃用的 `script-files` 安装原生包装器。跨平台 PATH 安装自动化（wheel 内置 wrapper、安装器脚本、`pipx`）作为后续项记录于 ADR §7.7，本轮未实现——触及此项即接近 Section 7 停止条件 #1（需超出范围的安装器/打包改动），故显式披露而非静默扩范围。
4. **包装器失败分支**（找不到启动脚本、解释器非绝对路径、`subprocess` `OSError` → exit 3）只有代码路径，没有测试注入。
5. **收据 `isolation.python_env` 只在 local 模式写入**；其它模式未改、未验证其收据结构。
6. **打包形态**：只验证源码树与 pip wheel 安装；zipapp、系统包管理器脚本等未测。
7. **独立复核（AC-10）**未做；本交接不构成 PASS。未做性能/并发/长期运行/fuzz 验证。
