# B3 — 证据附件不得使已签名验证失效

- 任务 ID：`B3`
- 状态：`draft`（派发前冻结）
- 优先级：P0 / correctness + security-adjacent
- 来源：B2 AC-3 的 `goal evaluate satisfied=true` caveat；RC3 B3 正向流程自失效
- 基线：`dev/v1.0` 的 B3 任务卡合并提交；精确 SHA 见 Issue
- 候选分支：`fix/b3-stable-criteria`
- Goal：`G-B3`
- 依赖：B0/B1/B2 已合并

## 1. 问题

当前 `goal evidence` 会把 evidence 追加到 `goal.success_criteria[i].evidence`（`coordination.py::add_goal_evidence`）。  
而验证记录里的 `goal_criteria_sha256` 是对**整个 `success_criteria`（含 evidence）**的摘要（`verify_run`）。

因此：

1. 先签一条有效 Verification（此时 `evidence=[]`，摘要为 D0）；
2. `goal evidence` 追加一条证据，`success_criteria` 变了，摘要变成 D1；
3. `_verification_current` 比较 `D1 != D0`，把记录判为失效；
4. `goal evaluate` 返回 `insufficient_evidence`，即使证据/收据/签名都有效。

B2 的正例正是这样：`goal evidence` exit 0，但 `goal evaluate` 仍 `satisfied=false`。

## 2. 目标

让**追加证据**不再改变“判据定义”的绑定：

- 有效签名 + 有效执行来源 + 追加证据后，`goal evaluate` 必须 `satisfied=true`；
- 不能通过重新签名/重新生成记录来“修复”；
- 改 criterion 的 `id`/`statement`/`required` 仍必须使记录失效；
- B0/B1/B2 的已有记录（legacy 摘要）仍可用，或有一条明确的兼容/迁移路径；
- 不放宽 B2 的执行来源门禁。

## 3. 范围

允许修改：

- `project_memory/coordination.py`（`_verification_current`、`add_goal_evidence`、`evaluate_goal`、`verify_run` 的摘要字段）
- `project_memory/common.py`（如需要稳定摘要 helper）
- `tests/`（新增 B3 测试）
- `docs/decisions/`（ADR-0004）
- `docs/` 中与 criteria digest/evidence 语义相关的契约文档
- `pilot/evidence/B3/`（如沿用试点证据结构）或 `evidence/B3/`

不允许：

- 删除/跳过既有测试；
- 放宽 `authority`/签名/`execution_provenance`；
- 修改 B2 任务卡/判据/冻结候选；
- 用“自动重新签名”或“忽略 `goal_criteria_sha256`”绕过；
- 把 B3 做成 B4/B5 的 bundle。

## 4. 设计选项（PM-02 选一个并写 ADR）

1. **稳定判据摘要 + legacy 兼容**
   - 新摘要只覆盖 `{id, statement, required}`（排除 `evidence`，按稳定顺序）；
   - 新记录写 `goal_criteria_sha256` = 稳定摘要，可另写 `goal_criteria_legacy_sha256` = 旧全量摘要；
   - `_verification_current` 优先比稳定摘要；对无稳定摘要的旧记录，退回“全量摘要”或“清空 evidence 的全量摘要”兼容；
   - 改 statement/id/required → 两种摘要都不匹配；改 evidence → 稳定摘要不变。
2. **证据外置**
   - `success_criteria` 保持不可变；evidence 存到单独字段/文件（如 `goal['criterion_evidence']` 或 `.project-memory/evidence/`）；
   - `evaluate_goal` 从新位置读，旧 Goal 的 `criterion.evidence` 作为迁移回退；
   - 摘要仍覆盖 `success_criteria`，因为 evidence 不再在里面；
   - 需要迁移/兼容旧数据。
3. 1+2 组合。

**不能**选的方案：

- 直接删掉 `goal_criteria_sha256` 检查（失去判据绑定）；
- 追加证据后自动重新签名（需要私钥/人类，不可自动）；
- 让 `evaluate_goal` 忽略 `_verification_current`。

## 6. 防作弊判据

以下“修复”判 **FAIL**：

1. 删除 `goal_criteria_sha256` 检查；
2. `_verification_current` 永远返回 true；
3. 追加证据后自动重新签名；
4. 只对 B2 fixture 的 goal id 特判；
5. 让 `evaluate_goal` 不调用 `_verification_current`；
6. 放宽 B2 的执行来源门禁；
7. 删除/跳过既有测试；
8. 把“goal evaluate satisfied”改成“只要 goal evidence 成功就算 satisfied”。
