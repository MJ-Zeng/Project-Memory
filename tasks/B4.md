# B4 — 审计与 Goal 状态必须可验证、防篡改

- 任务 ID：`B4`
- 状态：`draft`（派发前冻结）
- 优先级：P0 / integrity
- 来源：RC3 B4（审计不是防篡改账本）+ B2/B3 的 Goal 状态一致性观察
- 基线：`dev/v1.0` 的 B4 任务卡合并提交；精确 SHA 见 Issue
- 候选分支：`fix/b4-audit-integrity`
- Goal：`G-B4`
- 依赖：B0–B5B 已合并

## 1. 问题

1. **Goal 状态是可变 JSON**：`goal.status` 直接写在 `.project-memory/goals/G-*.json`；手改成 `achieved` 后，`goal show/list` 仍显示 `achieved`。`evaluate_goal` 虽给出 `recorded_status_consistent`，但消费方可能只看 `status`。
2. **执行审计无防篡改**：`_audit_attempt` 只向 `.project-memory/audit/verification_attempts.jsonl` 追加 JSON，没有 `prev_hash`、没有 head/checkpoint；删除一行、重写一行、整文件重建都无法检测。
3. **没有 `audit verify`**：现有 `audit` CLI 是知识文档审计，不是执行账本审计。
4. **关键转换没有可验证锚**：`achieved` 只依赖本地状态 + evaluate；没有签名/外部锚来证明“这条历史没有被重建”。

## 2. 目标

- Goal 状态不能只信原始 JSON：`goal show` / `evaluate` 必须给出**可信/有效状态**；
- 执行审计必须**防篡改**：删除、重写、重建可检测；
- 关键转换（至少 `achieved`）要有**可验证的链头/签名 checkpoint**；
- Agent 不能自动生成有效 checkpoint；人类/anchor 才能；
- 合法流程仍可用；B5B/B5A/B3 不回归。

## 3. 范围

允许修改：

- `project_memory/coordination.py`（`_audit_attempt`、`goal_show`、`evaluate_goal`、`transition_goal`）
- 新的 audit verify/chain helper（可放 `coordination.py` 或新模块）
- `project_memory/authority.py`（如 checkpoint 需要 anchor 签名）
- `project_memory/cli.py`（`goal show`/`audit verify`/`audit head` 等）
- `tests/`、`docs/decisions/`、`docs/` 运维文档
- `evidence/B4/`

不允许：

- 修改 B0–B5B 任务卡/判据/冻结候选；
- 删除/跳过既有测试；
- 放宽 authority/签名/来源门禁/B5B 默认拒绝；
- 把 Release/部署/B5C 夹带进来；
- 用“本地 hash 链”冒充“防重建”（必须说明威胁边界）。

## 4. 设计选项（PM-02 选一个并写 ADR）

1. **Hash 链 + 签名 checkpoint**
   - 每条 audit 记录写 `prev_hash`、`entry_hash`；
   - `audit verify` 从 genesis 重算链；
   - 关键转换（`achieved`/`approved`）写 `audit/head.json`，包含链头 hash、goal id、时间、签名；
   - checkpoint 由 anchor/人类签名；Agent 无私钥；
   - 删除/重写/重建会导致链/ checkpoint 不匹配。
2. **外部锚（Git commit/tag/PR）**
   - 每次关键转换把 audit head 写入 Git 提交/标签；
   - 依赖仓库历史，不额外签名；
   - 需说明离线/重写历史边界。
3. **派生 Goal 状态**
   - `goal_show` 返回 `effective_status` / `status_trusted` / `status_problems`；
   - raw `status` 只作声明；`achieved` 仅在 evaluate satisfied + audit 链有效 + checkpoint 有效时为 effective；
   - 可与 1/2 组合。

必须说明：
- 只加 hash 不验证 = FAIL；
- 攻击者能重算整条链时，必须有签名 checkpoint 或外部锚；
- 删除 audit 文件后“空链有效”必须被拒绝；
- 旧仓库/旧记录的迁移/回滚。

## 5. 验收标准

| AC | 判据 | 方法 | 通过条件 |
|---|---|---|---|
| AC-1 | 直接改 Goal status 不被信任 | 手改 `status=achieved`，无证据 | `goal show` effective != achieved / `status_trusted=false`；evaluate 不 satisfied |
| AC-2 | 删除 audit 行可检测 | 删中间一行 | `audit verify` 失败；指出断链 |
| AC-3 | 重写 audit 行可检测 | 改字段/重算该行 hash | verify 失败（链/签名） |
| AC-4 | 整文件重建可检测 | 重建一条自洽链，不更新 checkpoint | verify 失败（checkpoint/head 不匹配） |
| AC-5 | 合法流程通过 | 正常 transition + audit + checkpoint | verify 通过；effective=achieved |
| AC-6 | Agent 不能签 checkpoint | Agent 无私钥/无人类批准 | checkpoint 生成被拒；不能自动 achieved |
| AC-7 | 空/缺 audit 不被当通过 | 删除 audit 目录 | verify 失败；effective 不 achieved |
| AC-8 | 回归 | 既有 233 passed / 2 skipped + 新增 | 全绿；无删除/跳过 |
| AC-9 | B5B/B5A/B3 不回归 | 默认拒绝、包装器、B3 摘要 | 仍通过 |
| AC-10 | ADR/文档 | 威胁模型、被拒方案、残余风险、迁移 | 与实现一致 |
| AC-11 | 证据 | 命令/退出/审计/链/签名/哈希 | 可复现 |
| AC-12 | 独立复核 | PM-03/独立审查者 | 篡改/删除/重建矩阵 |

## 6. 防作弊判据

以下“修复”判 **FAIL**：

1. 只加 `prev_hash`，没有 `audit verify`；
2. `audit verify` 只检查最后一行；
3. 删除 audit 后“空链”返回通过；
4. 允许 Agent 生成/更新 checkpoint；
5. 只改 `goal show` 文案，`status` 仍被信任；
6. 删除/跳过既有测试；
7. 放宽 B5B 默认拒绝/B5A 入口/B2 来源门禁。

## 9. 判定语义

| 结论 | 条件 |
|---|---|
| **PASS** | AC-1..AC-12 全部满足；删除/重写/重建/手改均被检测；合法流程通过 |
| **FAIL** | 篡改未被检测；空链通过；Agent 可签 checkpoint；raw status 仍被信任 |
| **BLOCKED** | 环境/密钥/fixture 不可用 |
| **NOT VERIFIED** | 有 AC 未运行；整体不得记 PASS |
