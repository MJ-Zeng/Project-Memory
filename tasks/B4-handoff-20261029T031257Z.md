## 设计要点

- 每条审计记录含 `seq`、`prev_hash`、`entry_hash`；`entry_hash = sha256(canonical_json(entry 去掉 entry_hash))`，首条 `prev_hash` 为 64 个 `0`。
- `audit verify` 从 genesis 逐条复算，返回 `valid` / `valid_unanchored` / `invalid` 与 `*_at:<seq>` 位置；空文件、缺目录、无哈希旧账本都是 `invalid`。
- checkpoint 绑定**前缀**：`chain_head` + `chain_length` + `goal_id` + `status` + 证据摘要 + 迁移摘要。后续新增审计不会让已签名的 `achieved` 失效；重建/截断/改目标会让 checkpoint 不匹配。
- `achieved` 生效需同时满足：标准满足、链完整、checkpoint 由受保护 anchor 验签通过、`goal_id`/`status`/证据摘要/链前缀一致。否则 `effective_status=achieved_unverified`。
- Agent 侧只有 `checkpoint-request`（写待签名载荷）与 `checkpoint-attach`（只验签）。仓库中不存在生成私钥或签名的代码路径。
- 旧版无哈希账本：`audit migrate`（追加记录时也会自动触发）写 `verification_attempts.pre-chain.jsonl` 备份与 `migration.json`，迁移结果最多 `valid_unanchored`，迁移本身不被当作信任锚。
