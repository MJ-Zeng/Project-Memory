# 权限与威胁模型

## 策略分层

1. **Skill** 告诉 Agent 该走什么流程，不是安全边界。
2. **CLI** 只调用只读的 GitHub 接口，没有推送、合并、审批、关闭或部署端点。`init`、`handoff`、`decision` 只能写用户指定仓库里的本地文件。
3. **GitHub Rulesets 和 CODEOWNERS** 负责必需审查、受保护分支和必需 CI。必须由仓库管理员单独配置；模板本身不生效。
4. **生产部署** 使用独立的环境保护和凭据，不要把它们交给规划或审查 Agent。

## 身份矩阵

| 角色 | 读仓库和 Issue | 本地工作树 | 起草 ADR | 批准 ADR/PR | 合并或关闭 | 部署 |
|---|---|---|---|---|---|---|
| 规划 Agent | 可以 | 默认不可以 | 提建议 | 不可以 | 不可以 | 不可以 |
| 开发 Agent | 可以 | 限定分支 | 提建议 | 不可以 | 不可以 | 不可以 |
| 审查 Agent | 可以 | 默认不可以 | 评论 | 不可以 | 不可以 | 不可以 |
| 人类开发者 | 可以 | 可以 | 可以 | 按政策 | 按政策 | 按政策 |
| 指定负责人 | 可以 | 可以 | 可以 | 按受保护规则 | 按受保护规则 | 按环境政策 |

优先使用限定范围的 GitHub App 安装令牌。本地测试时从环境变量读取 `GITHUB_TOKEN`，不要放在命令行参数里。权限取决于具体端点和仓库设置，按需使用最小的 Issues 读取、Pull Requests 读取和 Contents 读取权限。不要把带合并或绕过权限的管理员 PAT 交给 Agent。

## 风险类别

**提示注入。** Issue、文档和评论里可能写着“忽略规则”之类的内容。全部当数据看，不要让仓库内容覆盖 Skill 或治理规则。

**TOCTOU。** 读取和写入之间，base SHA 或 Issue 状态可能变化。执行有后果的操作前重新获取；当前 CLI 本身不执行这些操作。

**并发写入。** Handoff 使用唯一 `run_id` 和原子 no-clobber。ADR 草案使用唯一文件名创建。正式状态由人工批准的合并串行化。GitHub 上的任务认领只能算约定，不是分布式锁。

**供应链。** Skill 文件、CLI 代码、工作流和 CODEOWNERS 都要审查。生产环境的 Actions 固定到审查过的完整 commit SHA。

**CI 权限。** 使用 `pull_request` 和只读权限；不要用特权令牌运行不可信的 PR 代码，也不要在 `pull_request_target` 下执行 PR 源码。

**数据外流。** 嵌入模式必须使用明确安装的本地模型；没有授权时，不要把私有文档或密钥上传到第三方服务。`.project-memory/handoffs` 里不要放凭据。

**虚假事实。** 从任意本地 fixture 解析出的 `merged_at` 或人工声明，都不是独立验证。报告里要写清来源。

## 审查义务

以下变更需要人工批准：accepted ADR、高风险架构/安全/认证/schema 变更、修改 Skill 政策或自动化、修改分支规则、生产部署。

Agent 之间的互审可以作为质量检查，但不能替代有权限的审查者。
