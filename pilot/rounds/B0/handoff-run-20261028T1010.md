## 6. 已知风险与可能的绕过（主动披露）

1. **remote 是本地配置，不是认证**：同权限 Agent 可改写 `.git/config`；但根提交必须同时匹配，若连对象库一起复制，内容上已是同一仓库。身份只回答“是否同一仓库”，不回答“谁执行”。
2. **身份无签名**：`repo_id` 与收据内容哈希均无密钥；伪造收据仍可能“内容自洽”。本轮没有放宽 `authority`：`_verification_ok` 仍要求签名信任锚，`execution_provenance.trusted` 仍恒为 false。
3. **旧收据在同一路径继续有效**：按任务卡 §8 选择“标记 `legacy_path_bound`”而非一律拒绝；跨路径已被拒绝，同路径行为与升级前一致，未引入新的跨路径放行。
4. **整仓复制视为同一仓库**：这是 AC-1 的目标，不是绕过；不同仓库靠 remote/根提交区分。
5. **根提交取自 `HEAD` 可达历史**：不同 Clone 若检出互不相关的历史（多个根）且 HEAD 指向不同根，身份会不同；同 commit 的 Clone 不受影响。
6. **`git remote get-url` 会应用 `insteadOf` 重写**：ssh/https 形式仍归一到同一 `host/path`；若本机配置改写目标，可能影响 remote 部分（根提交仍绑定内容）。
7. **证据包自引用**：`diffstat.txt` 在打包中途生成，`commands.jsonl` 之后又追加 3 条打包命令，且 `sha256sums.txt` 不覆盖自身；已在 `README.md` 注明。
